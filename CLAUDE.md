# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Slip-line (method of characteristics) analysis of bearing capacity for foundations on weightless/gravity soil. Python + numpy + matplotlib. `manual.tex` is the LaTeX user manual (theory, API, examples with expected output, figures) for all solvers, the velocity fields and the pipe simulations — consult it for the derivations. When the API or results change, update `manual.tex` and `README.md` too, and rerun the manual's examples so their expected output still holds. `pipe_formulas.tex` (Norwegian) gives closed-form H, V (lateral push, front half, and a contact from λ to φ = `phi_start` to `theta_max`) and Q (vertical) for the Tresca pipe with a surface falling away at θ, checked against the code's contact stresses, the length L of Region III along the surface (checked against `OneSidedDiskSolver.L`), the area of the plastic zone (`ClosedFormNet.area`, checked against the sum of the net's triangles in `plastic_work()`), the surface velocity there (checked against `InclinedDiskVelocityField`) and, in chapter 7, the dissipation of the lateral upper-bound mechanism with uniform friction (checked against `InclinedDiskVelocityField.dissipation()`); its figures come from `plot_pipe_formulas.py`, `plot_pipe_contact.py`, `plot_pipe_extent.py` and `plot_pipe_surface_velocity.py`, and it builds like the manual.

Managed with `uv` (Python 3.13; numpy and matplotlib declared in `pyproject.toml`, pytest as a dev dependency). There is no ruff config (defaults). `tests/` holds the checks as pytest tests: `uv run pytest` (~12 s, of which `tests/test_motion.py` ~10 s; `pyproject.toml` sets `testpaths = ["tests"]`, so the root `test_*.py` scripts are not collected). Each file also runs as a script and prints `ok` per test: `uv run tests/test_dynamics.py`.

## Commands

- Interactive CLI (strip footing or partly-penetrated disk, Tresca only): `uv run main.py`
- The `test_*.py` files in the repo root are **not pytest tests** — they are standalone scripts that print tables and/or save PNGs (e.g. `test_mc.py` writes `plots/plot_mc_phi*.png`). Run one with `uv run test_mc_disk_parallel.py`.
- `plot_*.py` scripts (and some `test_*.py`) regenerate the PNG figures in `plots/` (they use the `Agg` backend, so they save rather than show).
- `dbg.py` dumps Region I mesh nodes of a disk solve to `dbg.out`.
- `uv run run_penetration.py` simulates a pipe sinking under its own weight with heave (smooth, and r = 0.75) and prints the steps. `uv run run_penetration_closed_form.py` does the same with `PipePenetrationClosedForm` (same output, ~10× faster). `uv run animate_penetration.py` pushes a pipe down from P = 0 to P/R = 0.5 with `PipePenetrationClosedForm` (displacement controlled, via `advance`) and writes `plots/penetration.gif` and its last frame `plots/penetration.png`; D, cu, r and the final P/R are set at the top.
- `uv run run_lateral.py` sinks a rough pipe (r = 0.8, W = 2.8 kN/m), pushes it 0.2 m sideways and then 40 mm back, free to move vertically. `REVERSING` at the top picks the net (True: friction that reverses, ~3 min; False: free net angle, ~7 min). `uv run run_lateral_closed_form.py` does the same with `PipePenetrationClosedForm` and `PipeLateralClosedForm` (uniform friction, ~1 s).
- `uv run plot_yield_envelope.py` draws the H–V yield envelopes along the lateral push (cu = 5 kPa at 0, 4, 10 mm; cu = 1 kPa at 0, 50, 200 mm) to `plots/yield_envelope.png` and prints the table in `manual.tex` (~1 s).
- `uv run plot_projection.py` draws the closest-point projection on a schematic envelope and `PipeDynamics` against Newmark's sliding block to `plots/projection.png`.
- `uv run run_dynamic.py` pushes the pipe with a load Fx = 0.3·(1 − cos(πt/T_rise)) in time with `PipeMotion` and prints the steps: cu = 1 kPa with T_rise = 50 s and 1 s, and cu = 5 kPa (~4 s). `uv run plot_dynamic.py` draws the cu = 1 kPa runs (u(t), w(t), the soil force through the envelopes) to `plots/dynamic_push.png`.
- Format/lint: `ruff format`, `ruff check` (ruff is a global Homebrew install, not a project dependency). The whole repo passes both `ruff format --check` and `ruff check`; keep it that way by running both on the files you change before committing.
- Build the manual: `pdflatex manual.tex` twice (BasicTeX, in `/Library/TeX/texbin`; use `-output-directory` in the scratchpad to keep build files out of the repo). Figures come from `plots/` (`\graphicspath`), and listings must be ASCII only. The Read tool cannot render PDF pages here (no poppler); render them to PNG with a small Swift/PDFKit script (`swift` is available) to check the layout.

## Architecture

Package `slip_line/`:

- `yield_function.py` — `TrescaYield`, `MohrCoulombYield`: boundary stress states and Hencky/Mohr-circle relations.
- `boundary.py` — `FoundationBoundary` (strip, roughness `r`, half-width `B`) and `DiskFoundationBoundary` (diameter `D`, penetration ratio `p = z/D`, roughness `r`).
- `slip_line_field.py` — `Node(x, y, sigma, psi)` and the characteristic-net primitives: `alpha_slope`/`beta_slope`, `riemann_step` (Tresca), `*_mc` variants, and `riemann_step_mc_gravity`.
- `solver.py` (~2000 lines) — the core. Five solver classes, each building the field region by region (`_build_region_III` → `_build_region_II` (centred fan) → `_build_region_I`) and exposing `all_alpha_lines()` / `all_beta_lines()` for plotting:
  - `PrandtlSolver` — Tresca strip; `solve()` returns collapse load `q` (exact check: `cu·(π+2)` for smooth). Only valid for r = 0: Region I is uniform with ψ_A = π/2 − ½·asin(r), so r = 1 gives `cu·(1 + π/2)` where the rough strip's answer is also `cu·(π+2)`.
  - `MohrCoulombPrandtlSolver` — c-φ strip, weightless; checked against `analytical_Nc()`.
  - `MohrCoulombGravityPrandtlSolver` — c-φ strip with self-weight (γ>0), `solve(fit_foundation=...)`, `contact_pressure_curve()`.
  - `DiskPrandtlSolver` / `MohrCoulombDiskPrandtlSolver` — partly-penetrated disk (Tresca / MC). `solve()` returns a **dict** (`B_s`, `theta_max_deg`, `fan_angle_deg`, `Q_per_unit_length`, `Q_over_D`, `sigma_n_at_*`, …), and they provide `forces_on_half_disk()`. Both have `_resize_fan_and_wedge_to_match_region_I()`: Region I is built from the disk surface first, then the fan and Region III are resized to match it. The MC disk solver has a "parallel-β zone" mechanism for deep penetration/high roughness (`parallel_beta_zone` in the result). The Tresca disk's interface shear has the direction of a horizontal push by default (ψ_disk = π/2 − φ − ω, so `collapse_load_Q()` ≠ `2·forces_on_half_disk()['F_v']` for r > 0); `vertical_shear=True` gives that of vertical penetration (ω changes sign, friction on the disk acts upward, and the two agree).
- `velocity.py` — Geiringer velocity field on a Tresca net: `geiringer_step`, `PrandtlVelocityField` (strip) and `DiskVelocityField` (disk), both pushed down at `v0` (the disk also horizontally toward +x with `horizontal=True`, right half only, U = 0; for r > 0 `interface_slip()` gives the slip work against the interface shear, which is in `energy_balance()`); the outer α-line is the velocity discontinuity to rigid soil. `plastic_work_rate` / `DiskVelocityField.energy_balance()` check the sign of the plastic work and the virtual-work balance (keys `F_stress`, `F_virtual_work`, `F_upper_bound`, `negative_area_fraction`, `negative_interface_fraction`). For the vertical disk d < 0 in 30–60 % of the plastic area (p = 0.1–0.5) even for r = 0, so the field is not strictly kinematically admissible; `F_virtual_work` is 0.02–0.5 % below `F_stress` at `n_fan=18, n_disk=30` and converges to it with a finer mesh. `plot_velocity_strip.py` / `plot_velocity_disk.py` plot them with a hodograph.
- `penetration.py` — `PipePenetration`: quasi-static self-weight sinking of a pipe (roughness `r`) in small steps `dw`. Each step uses a flat-surface `DiskPrandtlSolver(vertical_shear=True)` at the effective embedment (invert below the contact level), raises the surface by the Geiringer upward surface velocity × `dw` (vertical only), scales that increment so the soil volume is conserved, and stops when the collapse load reaches the weight `W`. `PipePenetrationClosedForm` overrides `load` and `surface_uplift_rate` with the closed forms of `pipe_formulas.tex` (flat surface, vertical penetration), so it needs no net: same steps and results, 10–14× faster.
- `lateral.py` — `PipeLateral`: lateral push of a pipe that is free to move vertically (V = W constant), starting from a `PipePenetration` end state (`after_penetration`). Kinematic (upper bound): each step picks the direction β (below horizontal) and net angle ω that minimise H = (D − W·sin β)/cos β, where D = Σ|d|·A + cu·U·L + r·cu·∫|slip| on the Geiringer field of a `OneSidedDiskSolver` net. That net's contact chain runs from the trailing separation φ = −β (or the left contact angle on the original surface) to the right edge, all soil flows forward, and the free surface in front slopes at the fitted berm angle α. The trench behind stays open. The berm rises by the normal surface velocity, and the soil the pipe moves into is removed (volume-scaled). `move(state, du, dw, flow)` does this for any motion, the soil flowing with the fields in `flow` (a list of (field, path length), two at a corner of the envelope, none for lift-off); `advance` is `move` along the state's mechanism. The first step scans β; later steps search locally around the previous mechanism, which can miss a lower minimum (see Known issues). With the free net or reversing friction H starts slightly negative, because this mechanism is a few % weaker than the penetration's flat-surface stress solution; with uniform friction it is stronger, and H starts positive (0.36 kN/m at cu = 1 kPa). `reversed(state)` sets up a push back toward −x in the mirror image x → −x (map u, x and H back with a sign change); the trench is then in front (α < 0) and the push starts with H > 0 toward +x, a holding force. If the search ends on an invalid (incomplete) net, `mechanism` takes the best valid one it has seen. By default ω is free, so the net need not match r (it is nearly smooth, |ω| ≲ 10°) and r enters only through the slip work. `reversing=True` makes the net carry the interface friction instead: the slip along the pipe changes sign (the pipe slides forward relative to the soil near the invert, the soil slides up past it near the edge), so ω = +½·asin(r) below `phi_switch`, −½·asin(r) above, with a constant-ψ transition of half-width ½·asin(r) where the soil sticks to the pipe; `phi_switch` is where the field's own slip is zero (bisection per β). That gives a self-consistent field and a lower H than the free net. `OneSidedDiskSolver` reduces ω on the outer arc where the fan would be negative (parallel zone, as in `DiskPrandtlSolver`). With reversing friction and a flat surface the one-sided mechanism carries V ≈ 2.70 kN/m at H = 0 (mesh-converged) where the penetration's stress solution gives 2.80, so the stress solution overestimates the rough pipe's vertical capacity by a few %; H is then clearly negative at the start of the push and the direction changes fast, so `run(..., du=...)` is called with 0.25 mm steps for the first 50 mm (and the first 10 mm of the reverse push). `uniform=True` makes the net carry +r·cu toward the edge on the whole contact (ω = ½·asin r, only β searched). `PipeLateralClosedForm` is that model with `field()` replaced by `ClosedFormLateralField` (dissipation, Region III length and surface velocity in closed form, pipe_formulas.tex chapter 7); everything else is inherited, and it runs ~100× faster. Unlike the net it accepts a contact reaching above the front contact level (phi_start < −theta_max), which the net cuts off as incomplete; this happens at the start of a push back after the pipe has risen.
- `envelope.py` — `YieldEnvelope`: the H–V yield envelope of the soil for one `PipeLateral` state (step 1 of `PLAN_DYNAMIKK.md`), the convex polygon of the half-planes H·cos δ + V·sin δ ≤ D(δ) (H toward +x, V down, (H, V) from the pipe on the soil). `from_state(lat, state, n=720)` samples D forward with the state's one-sided mechanism (`dissipation()`), backward with `lat.reversed(state)` (δ = π − δ′, H → −H), and D = 0 where the pipe has no contact left; uniform friction only (~11 ms with `PipeLateralClosedForm`). Also `from_dissipation(deltas, D)` and `YieldEnvelope(vertices)`. `push_force(V)` is the displacement-controlled push of `mechanism()` (forward half-planes only, matches a fresh `mechanism(state)`); `H_range(V)` is the force-controlled range, which the backward half-planes can shift above zero (a holding force is needed) or empty (V = W outside: the pipe sinks), once the pipe has lost the contact behind it. The envelope is how the local minimum of `PipeLateral.run` was found (Known issues).
- `dynamics.py` — `PipeDynamics`: the pipe with mass on a fixed `YieldEnvelope` (step 2 of `PLAN_DYNAMIKK.md`), loaded by W, `Fx(t)` and the lift `F_L(t)`. Backward Euler: the soil force is `closest_point(env, F*, M)`, the point of the envelope closest to F* = F_ext + M·v/Δt in the metric of M⁻¹, and v = Δt·M⁻¹(F* − F); F* inside means rest. Forces in kN/m, masses in kg/m (t/m inside), energies in kJ/m. `pipe_mass(W, D, C_a=1)` gives M from the submerged weight (m = W/g + ρ_w·πD²/4 = 1090 kg/m for W = 2.8, D = 1) plus the added mass. `run(t_end, dt)` (last step shorter if t_end is not a multiple of dt) returns `DynamicState`s (t, u, w, u_dot, w_dot, H, V, `delta`, nan at rest); `energy(states)` gives work = dissipation + kinetic + numerical exactly (kinetic: the change from the first state). Masses and dt must be positive (ValueError). First order in Δt. The geometry is fixed, so it is valid for small motions only. `PipeMotion(lat, geo, M, Fx, F_L, ds=0.25e-3)` (step 3) makes it follow: it steps `PipeDynamics` on the envelope of the current geometry, and every path length ds it moves the geometry with `lat.move` (the soil flowing with the mechanisms of the envelope edges the velocity followed, split at corners) and makes a new envelope (~15 ms each). Without contact `env` is None (zero soil force) and the geometry is updated as soon as the pipe touches. It stops (`stop_reason = "backward"`) before a motion that needs a mechanism of the mirror image (u̇ < 0, sinking back into the gap behind, landing straight down in a symmetric hollow), which is step 4. `geometries` lists (t, LateralState, envelope) per update. The slow load follows the quasi-static push within 1 %; with cu = 5 kPa it follows the lift branch from u ≈ 1.3 mm, leaves the trench floor behind by microns and stops at u ≈ 1.5 mm.
- `plot.py` — matplotlib plotting (`plot_slip_lines`, `plot_disk_slip_lines`, `plot_mc_slip_lines`, …), one per solver type.

Conventions that matter across files:

- **y points downward (depth)**; angles are measured CCW in (x, y_down) space, which looks clockwise on screen. `plot.py` flips y for display.
- **Compression positive.** `ψ` is the angle of the major principal stress σ₁; `σ` is mean stress. Along α-lines `σ − 2·cu·ψ = const`, along β-lines `σ + 2·cu·ψ = const` (Tresca).
- Only the right half (x ≥ 0) is computed; plotting mirrors it.
- **Signed roughness in requests:** the user writes a negative `r` (e.g. r = −0.75) for the interface shear direction of vertical penetration. `DiskFoundationBoundary` only accepts 0 ≤ r ≤ 1, so this means `r=abs(r)` with `DiskPrandtlSolver(..., vertical_shear=True)`.
- **Contact stresses are shown as stresses from the pipe on the soil** (the user is a geotechnical engineer): σ_n as compression into the soil, and for penetration τ on the soil pointing toward the invert. `stress_distribution_curve()` returns σ_n and |τ|; `forces_on_half_disk()` gives forces on the disk; `interface_slip()["tau"]` is the signed shear on the soil along t = (cos φ, −sin φ).

## Known issues

`PLAN_DYNAMIKK.md` (Norwegian) is the step-by-step plan for the dynamic pipe model (two degrees of freedom, yield envelope, wave loads). Follow it one step at a time: documentation first (theory in `manual.tex` before the code), and the step is done only when the checks, docs and its status table are updated; get the user's go-ahead before starting the next step.

`VIDERE_ARBEID.md` (Norwegian) lists results that are known to be wrong or uncertain, literature checks and planned work, in a recommended order. Read the relevant item before changing the affected code, and update the file when an item is resolved. The ones most likely to bite:

- `main.py`'s strip option defaults to r = 1.0, which gives the wrong `PrandtlSolver` answer (see above).
- `plot_disk_Fv_vs_p.py`, `plot_disk_Fv_Fh_vs_p.py` and `plot_disk_forces_vs_z.py` use the default (horizontal-push) shear direction for r > 0, although the figures are labelled vertical resistance; so does `main.py` for a rough disk.
- Example 4 in `manual.tex` extracts Nγ with the half-width B, which gives twice the usual Nγ; the comparison with Vesic there is not valid.
- `PipeLateral.run` searches β locally from the previous step, so it can follow a local minimum (`VIDERE_ARBEID.md` 1.10). With cu = 5 kPa (W/(cu·D) = 0.56) that happens from u = 1.25 mm, and H is up to 43 % too high; with cu = 1 kPa the run is right until the contact behind is lost (~190 mm), and H is at most 2.7 % too high after that. A fresh `lat.mechanism(state)` (no guess) or `YieldEnvelope.from_state(lat, state).push_force(W)` finds the lowest minimum. The search is not fixed; 1.10 proposes leaving it, since the dynamic model uses the whole envelope.
